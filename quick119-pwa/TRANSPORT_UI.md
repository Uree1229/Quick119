# 접수 채팅 · GPS · 병원 참여

2026-11-17 / 팀 소스 커밋 `37492e19240490d656e7f4f85cb43f52e986bd0b`

현재는 인증 없는 가상 데이터 검증용입니다. 팀 서버와 QUICK119 서버 모두
`127.0.0.1`에서만 실행하며 LAN·운영 모드 접근을 차단합니다.

## 실행과 사용

프로젝트 루트의 PowerShell 터미널 두 개에서 실행합니다.

```powershell
# 터미널 1: 기존 가상 기록을 유지하고, 가상 자원의 관측 시각만 명시적으로 갱신
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-team-chat.ps1 -RefreshSyntheticResources

# 터미널 2: 키 없이 확인하는 가상 직선 경로 모드
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-chat-api.ps1 -SyntheticRoutes
```

각 터미널의 Ctrl+C로 종료합니다. 이미 실행 중인 서버가 있으면 먼저 해당 실행 터미널에서
종료하거나 서로 다른 `-Port` / `-TeamPort`를 지정합니다. 기존 DB를 삭제하지 않습니다.
스크립트 실행 예외는 해당 PowerShell 프로세스에만 적용하며 영구 실행 정책은 바꾸지 않습니다.

1. 홈의 ‘응급상황 접수 시작’을 누르면 `/transport/`에서 접수 채팅을 바로 엽니다. 기존 `/emergency`, `/voice-intake` 주소도 같은 화면으로 이동합니다.
2. 처음에는 시스템과 구급대원만 참여합니다. 새로운 가상 접수 건을 자동 생성하며, 환자 상태를 글로 입력하거나 채팅의 음성 입력을 사용합니다. 빈 입력칸에서 시작한 접수 음성은 인식이 끝나면 명령 처리기로 전달됩니다. 작성 중인 글에 음성을 덧붙이거나 병원과 대화할 때는 직접 보내기를 누릅니다.
3. 원형 ‘환자 정보 확인’에서 현재 정보를 열고, 채팅에서 항목을 정정합니다. 구조화된 초안이 있으면 ‘병원 탐색 시작’에서도 12항목을 확인할 수 있습니다. 예전 접수 건이나 구조화된 정보가 없는 보고는 기존 수동 입력창을 사용합니다. 최종 확인한 뒤 상위 후보 3곳을 지도에 표시합니다.
4. 해당 병원의 ‘의료진 화면 열기’를 새 창에서 엽니다. 서버 주소는 같은 출처로 고정됩니다.
5. 의료진 창에서 가상 담당자 이름을 입력하고 해당 문의의 ‘수용 가능’을 누릅니다. 이 단계에서는 병원이 아직 채팅방에 참여하지 않습니다.
6. 대원 화면의 ‘이 병원으로 목적지 확정’을 누르면 같은 채팅방에 병원이 추가됩니다. 확정된 병원은 확정 전에 시스템에 보낸 보고와 시스템의 접수 확인도 읽을 수 있습니다.
7. 의료진 창의 ‘도착 예정 · 이송 대화’에서 동일 이송 ID를 선택하고 답장합니다. 대원 화면은 ‘접수 채팅’ / ‘GPS 지도’로 전환할 수 있습니다.

가상 이송 ID만 URL에 남습니다. 새로고침 후 같은 ID의 서버 기록은 다시 조회하지만,
초안·미확인 전송 요청·GPS 상태는 새로고침 후 복원하지 않습니다.
병원 문의 전에는 채팅과 마이크의 최종 인식문을 같은 접수 건의 팀 음성 초안으로 처리합니다. 12항목은 나이, 성별, 증상, 의식, 호흡, 혈압, 맥박, 산소포화도, 체온, 호흡수, 혈당, 발생 시각입니다. 자유 보고를 보내거나 “맥박 92로 수정해 줘”, “방금 입력 취소”, “질문 다시 해 줘”처럼 명령을 입력할 수 있습니다. 여러 인식 후보가 충돌하면 재확인하고, 용어 교정 후보와 수치 확인 표시는 원문과 함께 제공합니다.

“확정”은 화면 버튼으로 초안 버전을 확인합니다. “전송해줘”는 12항목 확인창을 열고 **확인하고 병원 탐색**을 누르면 현재 환자에 반영한 뒤 후보를 조회합니다. 후보 병원에 수용을 문의하려면 해당 병원의 문의 버튼을 누릅니다. 병원 참여 중에는 일반 채팅으로 동작합니다. 브라우저 마이크는 HTTPS 또는 localhost와 지원 브라우저가 필요합니다. 휴대폰 HTTP 시연에서는 키보드 받아쓰기로 입력한 뒤 보내기를 누를 수 있습니다.

미전송 초안·결과 미확인 전송은 정리한 뒤 탐색할 수 있습니다. 병원에 수용 문의를 보낸 뒤에는 이 화면에서 환자 정보를 다시 덮어쓰지 않고 조회만 제공합니다. 기존 서버의 문의 후 정보 정정 절차는 별도 후속 작업입니다.

## 경로 모드 구분

`-SyntheticRoutes`는 기존 `/api/routes/car`의 **명시적인 로컬 테스트 모드**입니다.
팀의 가상 병원 10곳 좌표만 허용하며 지도에는 직선을, 거리·시간에는 단순 추정값을 표시합니다.
화면에 ‘가상 직선·시간 추정 테스트 / 실제 도로 경로 아님’을 계속 표시합니다.
실제 길안내나 이송 시간 판단에 사용하면 안 됩니다. 지도 타일은 인터넷 상황에 따라 보이지 않을 수 있습니다.

해당 옵션을 빼면 원래 카카오 경로 처리를 그대로 사용합니다. 기본 `start-chat-api.ps1`은
외부 API와 `.env` 로딩을 끄므로 이 경우 경로 조회는 비활성 안내가 나옵니다.
기존 HTTPS/API 실행 스크립트, `api_integrations.py`, 키 설정은 변경하지 않았습니다.
이번 검증에서는 실제 API 키나 `.env`를 읽거나 실경로 API를 호출하지 않았습니다.

## 지도·채팅 화면 디자인 (2026-11-17 개편)

홈·상단 브랜드 헤더·색상(네이비 `#17375e`, 레드 `#e5484d`)은 그대로 두고 접수 채팅 화면(`/transport/`)을 앱형으로 바꿨습니다. 채팅 UI가 켜진 `/emergency/hospitals`에 들어가는 같은 화면도 새 디자인(높이 제한 카드)을 씁니다.
요소 ID·이벤트 계약, 서버 API, GPS 필터·호출 제한, 전송·재시도 규칙은 그대로입니다. 탐색·문의 흐름에 더한 동작은 이미 문의 중인 병원의 `수용 문의` 버튼 잠금 하나이고, 지도 핀의 접수 위치는 탐색 때 이미 조회하는 환자 정보의 좌표를 씁니다.

- **전체 배치**: 화면 높이에 맞춘 고정 레이아웃입니다. 이 화면에서는 하단 메뉴와 설치 안내 패널(`pwa_controls.html`) 대신 채팅 입력창이 아래에 붙고, 홈은 상단 뒤로가기로 이동합니다. 다른 화면은 그대로이며 `base.html`에는 기본값이 같은 block만 추가했습니다.
- **헤더**: 화면 제목과 연결 상태 점, 참여자 칩(병원 합류 시 병원 이름 강조), 48px 원형 환자 정보 버튼, `지도`/`채팅` 전환 버튼(새 의료진 메시지 배지)과 4단계 진행 표시(보고 → 탐색 → 문의 → 확정)를 둡니다. 진행 단계는 페이지에 이미 있는 대화·후보·문의 상태로만 계산합니다. 목적지가 확정되면 병원 칩에 `목적지` 표시(CSS만, 텍스트는 병원 이름 그대로)가 붙어 제목 아래 한 줄로 내려오고, 다 끝난 4단계 표시와 문의 목록은 접힙니다. 대화가 끝나 병원 칩이 사라지면 확정 병원 행만 남깁니다.
- **채팅**: 시스템(레드 +), 병원(그린) 아바타 말풍선, 구급대원은 오른쪽 블루 말풍선, 문의·확정 같은 시스템 이벤트는 가운데 얇은 띠(시간은 문장 끝)로 표시합니다. 시간은 말풍선 옆(받은 메시지는 오른쪽 아래, 보낸 메시지는 왼쪽 아래)에 둡니다. 같은 발신자의 연속 메시지는 묶습니다. 접수 ID·대화 안내·연결 종료는 대화 맨 위 카드에 둡니다. 지도에 있는 동안 온 의료진 메시지는 채팅으로 돌아와도 읽음 처리하지 않고 배지와 `새 메시지 확인`을 유지합니다.
- **입력창**: 마이크 · 자동 높이 입력칸 · 보내기 한 줄입니다. 음성 인식 중에는 붉은 듣기 패널(파형, 중간 결과)과 `마치기` 버튼으로 바뀌며, 자동 전송하지 않는 기존 규칙은 같습니다. 가상 데이터 경고는 입력창 묶음 위 테두리의 작은 탭(`가상 환자·병원 전용 · 실제 환자정보 입력 금지`)으로 모든 단계와 입력 중에 항상 보입니다. 음성인식 제공자 처리 안내는 대화 맨 위 카드의 `대화 안내`에 있고 마이크 버튼이 이를 참조합니다. 음성인식을 쓸 수 없으면(휴대폰 HTTP 시연 등) 마이크에 주황 `!`가 붙고, 버튼 이름이 `받아쓰기 안내`로 바뀝니다. 터치·Enter·Space로 안내를 여닫으며, 스크린리더에는 펼침 상태를 알립니다. `병원 탐색` 바는 입력창 위 한 줄(제목 + 44px 버튼)이며, 보고 전에도 쓸 수 있고 보고 후에 강조됩니다. 막힌 이유와 오래된 탐색 경고만 바 아래 줄에 보이고, 요청 중 상태와 기본 안내는 스크린리더로 전달합니다. 입력·음성인식 중 탐색 바가 접혀도 변경된 안내를 읽을 수 있습니다.
- **문의 목록**: 병원마다 한 줄씩 쌓던 목록을 가로 한 줄 칩(57px)으로 바꿨습니다. 수용 가능 응답 칩(44px `목적지 확정`)과 확정 병원 칩이 맨 앞에 오고, 다음 칩은 끝이 살짝 보입니다. 수용 가능 병원이 둘 이상이거나 320px 화면이면 확정 버튼이 있는 칩이 한 줄 전체를 씁니다. 화면과 스크린리더 모두 확정 → 수용 가능 → 나머지 순서이고, 같은 상태 안에서는 서버 순서를 유지합니다. 다른 병원에서 응답해도 사용 중이던 확정 버튼의 키보드 포커스를 유지합니다. 화면이 짧으면 문의 목록이 먼저 줄고, 채팅 열은 입력창 묶음보다 작아지지 않습니다.
- **입력 중 집중 모드**: 입력칸에 포커스가 있고 화면 높이가 150px 넘게 줄면(키보드) `transport-workspace.js`가 `#transport-workspace`에 `data-kb="open"`을 붙입니다. 그동안만 네이비 바·개발 안내 줄을 숨기고, 헤더를 한 줄(연결 점, 제목 또는 목적지 칩, 현재 단계, 환자 정보·지도 아이콘)로 접고, 입력창 묶음은 경고 탭·미전송 안내·입력칸(초안 3줄까지, 보내기는 아이콘, 재시도는 320px에서도 글자 표시)만, 문의 목록은 `목적지 확정` 줄만 남깁니다. 줄어든 높이가 80px 안쪽으로 돌아오거나 포커스가 150ms 넘게 입력창 밖에 있으면 원래대로 돌아오고, 확대 중에는 판단하지 않습니다. 단독 채팅과 `/emergency/hospitals`의 채팅 모두 키보드가 열려 있는 동안 `visualViewport`의 높이를 따릅니다. 병원 목록에서는 키보드가 열리거나 크기가 바뀔 때 대화 기록과 입력창을 함께 보이게 합니다. 둘 다 들어갈 공간이 부족하면 입력창을 우선하며, 화면 높이가 그대로일 때는 사용자가 움직인 스크롤 위치를 유지합니다. 채팅 공간이 짧을 때는 연결 알림·병원 응답과 입력 보조 안내를 각각 스크롤할 수 있습니다. 3초 조회가 한 번 실패해도 입력칸은 잠그지 않고 보내기만 막아 작성 중인 초안과 키보드를 유지합니다. 보내는 동안 입력칸을 잠그는 기존 동작은 한글 조합 중 글자 처리 위험 때문에 그대로 둡니다.
- **지도**: 상단 지도 + 하단 시트 구조입니다. 탐색 후 상위 3곳을 지도에 번호 핀(1~3)과 접수 위치로 표시하고, 시트에 순위·가상 이동시간·응급병상 여유·판단 근거와 `경로`/`수용 문의` 카드를 둡니다. 핀을 누르면 해당 카드가 강조될 뿐 문의·경로 요청은 하지 않습니다. 문의 중인 병원 카드는 상태를 표시하고 같은 병원 중복 문의 버튼을 잠급니다.
- **경로·안내**: 경로 카드에 남은 거리·예상 시간, 가상 경로 경고, 실시간 안내 시작/종료, 카카오맵 링크를 둡니다. 안내 중에는 지도에 GPS 상태와 `내 위치 따라가기` 버튼이 뜹니다. 채팅 화면에서 목적지를 확정해도 지도를 열면 새 경로에 맞춰 화면을 잡습니다. 목적지 확정 뒤(새로고침 후 포함) 경로가 없으면 시트 맨 위 `이송 목적지 · 경로 보기`로 확정 병원 경로를 다시 열 수 있고, GPS 실패 뒤 재시도에도 씁니다.
- **환자 정보 팝업**: 같은 native dialog를 하단 시트형으로 바꿨습니다. 조회 모드는 저장값 타일과 보고 원문만, 최종 확인 모드는 자동 추출값(파랑)·충돌/불일치(주황)를 구분한 입력칸과 항상 보이는 하단 버튼을 표시합니다.
- 기존 `car_route_panel.html`과 `car-routes.css`는 채팅 UI가 꺼진 응급실 목록 화면용으로 그대로 둡니다. `car-routes.js`의 후보 핀과 지도 상태 영역은 새 화면에만 있고, 경로 상태 속성(`data-route`)은 기존 패널에도 붙지만 기존 CSS는 쓰지 않습니다.

## 동작과 수명

- 두 패널은 한 페이지에서 한 번 생성하고 표시만 바꿉니다. 전환으로 GPS watcher,
  채팅 객체, 커서, 지도 인스턴스를 다시 만들거나 페이지를 이동하지 않습니다.
- 채팅 화면에서도 GPS 정확도·위치 튐·경로 이탈 검사와 기존 호출 제한이 계속 실행됩니다.
- 지도 숨김 중에는 위치·경로 데이터를 갱신하고 지도 렌더링을 보류합니다. 복귀 시
  `invalidateSize({pan:false, animate:false})`와 최신 경로를 적용합니다.
  확대와 따라가기 ON/OFF를 유지하고, ON이면 마지막 유효 GPS, OFF이면 수동 중심을 복원합니다.
- 기존 팀 API로 수용 문의 → 의료진 수용 → 대원 목적지 확정을 진행합니다.
  확정 전 메시지는 `hospital_session_id: null`인 구급대원 보고로 저장합니다. 확정 후에는 해당 병원 참여 구간에 메시지를 보냅니다. 참여자가 바뀐 초안은 내용을 확인한 후 전송해야 합니다.
- 병원 조회는 원래 팀 서버의 참여 권한 확인을 먼저 통과해야 합니다. 현재 확정 병원에만 이전 구급대원 보고를 추가로 제공하며, 다른 병원의 대화나 다른 환자 기록은 합치지 않습니다. 서버 원본·DB 스키마와 기존 메시지 커서는 유지합니다.
- 페이지가 전면에 있으면 어느 패널에서도 중첩 없이 3초 폴링합니다. `has_more` 페이지를
  먼저 소진하고 사건·메시지 커서를 따로 갱신합니다. ID로 중복 제거, `order_key`로 정렬합니다.
- 지도에 있는 동안 새 의료진 메시지를 받으면 배지를 표시합니다. 최초 과거 기록은 세지 않습니다.
  채팅에서 마지막 메시지를 보거나 ‘새 메시지 확인’을 눌렀을 때 페이지 안의 미확인 표시를 지웁니다.
  이는 서버 읽음 확인 기능이 아닙니다.
- 미확인 전송은 원래 ID·본문·참여 구간·발신 이름 그대로 재시도합니다.
  POST 성공만으로 GET 커서를 앞당기지 않으며 저장 영수증을 대조한 뒤 요청을 지웁니다.
  병원 참여 구간이 바뀐 초안은 사용자 확인 전까지 전송을 막습니다.
- ‘안내 종료’는 GPS만 종료합니다. ‘채팅 연결 종료’는 로컬 채팅 폴링만 중단하며
  서버 대화방·이송을 취소하거나 GPS를 끄지 않습니다. 재연결 시 놓친 메시지를 조회합니다.
- 앱 최소화·화면 잠금·페이지 이탈은 기존 GPS 안전 중단을 유지합니다.
  채팅 조회도 일시정지하며 복귀 시 커서로 재조회합니다. GPS는 사람이 다시 시작해야 합니다.

## 의료진 화면 재사용과 정보 보관

`/hospital/`은 고정 커밋의 `hospital-ui` HTML·모듈·CSS를 재사용합니다.
원본 폴더를 수정하지 않고 응답 시 최소 어댑터를 적용합니다.

- 원본의 모든 `localStorage` 참조를 페이지별 Storage 호환 메모리 객체로 교체합니다.
  원본 전송 복구 모듈의 저장 후 읽기 확인도 동일 메모리 객체로 동작합니다.
- 서버 주소 설정을 같은 출처로 제한하고 CSP `connect-src 'self'`를 적용합니다.
- 이번에 연결한 수용 문의·이송 대화만 표시합니다. 자원·제한·계측·도착 처리의 미연결 조작은 숨깁니다.
- 양쪽 화면의 메시지·초안·환자정보를 localStorage/sessionStorage/IndexedDB에 추가하지 않습니다.
  동적 HTTP 응답은 `no-store`이며 기존 SW 정적 허용 목록은 변경하지 않았습니다.
- 팀 DB와 QUICK119 DB는 계속 별도입니다. 인증·권한이 구현되기 전에는 실제 환자를 넣지 않습니다.

## 남은 제한

실제 갤럭시 설치 PWA·GPS 센서·화면 잠금·가상 키보드는 실기기 미검증입니다. 입력 중 집중 모드도 실제 키보드가 아니라 화면 높이를 줄이는 방식으로만 확인했습니다(삼성 키보드·아이폰 미확인).
